How it works

Accounts. Passwords are never stored. The server keeps a random 16-byte salt and a PBKDF2-HMAC-SHA256 hash (200,000 iterations).

Vault key. Your vault passphrase goes through scrypt with a fresh salt to give a 256-bit key.

Standard mode. Ciphertext plus an HMAC tag. A wrong passphrase fails the tag, so an attacker knows exactly when a guess is right.

Honey mode. No tag. The secret is turned into numbers, XORed with a keystream (SHAKE-256), and any key decodes back into a well-formed secret of the same type: a wrong passphrase gives another random-looking PIN, key or phrase. Card numbers are rebuilt with a Luhn check digit, so fakes pass the same validity test as the real one.

Limits: honey encryption only protects structured secrets, and it does not help if the attacker has other ways to check a guess, such as logging in to the real bank. Use a strong passphrase as well.
